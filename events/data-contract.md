# 网站与周刊的内容数据约定

内容在本仓库按期维护，网站 `sunling/inspireplanet.cc` 负责读取、展示与卡片导出，不另行手工维护同一份正式内容。

## 文件与身份

- `events/{year}/{YYYYMMDD}-epXX/summary.json`：网站单期详情页的结构化分享纪要。
- 同目录 `quote-cards.json`：金句卡片与启发星球周刊的数据。
- 期次用“年份＋期数”定位，例如 `2026/40`；JSON 中保留兼容的 `episode: "EP40"`，年份从目录取得。不能只靠 `EP40` 跨年关联数据。
- `summary.json` 的 `date` 使用目录日期，格式为 `YYYY-MM-DD`。不根据历史归档日期推断或纠正真实活动日期；发现错误须有依据并单独更正。

## 字段

金句只维护 `quote-cards.json`，不再维护重复的 Markdown 数据副本；历史帖文、标题与话题词不混入金句字段。

JSON 使用 UTF-8。金句文件是数组，每项只含非空字符串 `name`、`title`、`quote`、`detail`、`episode`。`detail` 是读者可直接阅读的会议语境，不带“出处：……”、转写时间戳或时间区间。

纪要文件是对象，包含非空字符串 `episode`、`date`、`title`、`overview` 和非空数组 `topics`。新纪要每个话题包含 `speaker`、`title`、`context`、`keyPoints`、`quote`、`discussion`；`keyPoints` 是非空字符串数组。`highlights` 是字符串数组，没有额外片段时可为空。没有现场讨论时 `discussion` 可为空，不为满足格式补造问答。校验兼容历史话题的 `summary` 字段。

具体写法分别见 [纪要 skill](../.agents/skills/inspireplanet-summary/SKILL.md) 与 [金句 skill](../.agents/skills/inspireplanet-cards/SKILL.md)。纪要中的代表金句可以与卡片重复；两份文件分别服务整场阅读和独立卡片，不要求数量或顺序一一对应。修改事实、署名或匿名边界时检查两份文件及相关渠道稿。

## 事实与审核

会议事实回查本期 `transcript.txt`；已有文章只辅助理解。原始转写不随编辑稿润色，历史期无转写时不补造出处。需要留存具体时间区间时，写入本期 README 折叠的编辑核对记录，不放进金句展示字段。Git 历史保留修订记录。

完整发布包生成两份 JSON；单独任务只生成指定内容。文件生成后仍须核对事实、署名、隐私及公开授权，生成文件不等于获准公开。README 只维护导航、本期命令与发布备注，不记录制作进度。

## 网站读取与修订

网站当前从 GitHub 的 `sunling/inspire-planet/main` 扫描每期目录并读取 JSON，目录列表缓存约 5 分钟，解析后的数据按文件 SHA 缓存。因此合并到 `main` 会使内容被网站读取，不应把未经确认的草稿合入该分支。

审核后运行 `python3 scripts/check-content.py`，通过分支与 PR 提交。用户确认具体公开范围后再合并；本地修改或 Draft PR 不会更新网站正式数据。修订也在本仓库完成，网站随后读取新版本；未显示更新时先核对文件是否已合入 `main` 与缓存刷新情况。

历史期没有 `summary.json` 时保留缺失，网站现有逻辑会尝试内置纪要、历史 `recap.md` / `gzh-epXX.md`，没有纪要时详情页展示金句或整理中提示。没有金句时不生成空卡片补位。两类数据都未必每期齐全。

新增或改名字段、移动文件前，同时修改生成 skills、校验器和网站读取代码；普通文案修订保持现有结构。

## 会后群消息

当期 `group-message.md` 只保存一份可直接复制的正文：一个具体片段和一处真实回应、追问或变化，结尾只留一个已核实的本期回顾链接。没有互动时选一个完整经历，不编对话。通常 150–300 字，不放内部备注、全期目录、备选稿或多个渠道链接；无确认链接时不猜测，交付时单独说明。

正文从本期转写核对，遵守同样的署名和公开边界。由当期 README 导航；准备或提交稿件不等于已经发群，不自动发送。该 Markdown 不新增 JSON 字段，也不代表网站会自动展示群消息。

## 播客发布文字归档

获准公开后可在当期目录保存 `podcast.md`：只含最终标题、简介、参与者、与发布音频一致的成品时间轴、本期详情页链接、实际使用的可公开固定加入二维码图片引用（平台不支持插图时为实际使用的加入页备用链接），以及“发布信息”指向同目录 `episode-publication.json`（发布后补入真实单集链接、实际音频时长和实际发布日期，约定见下文）。固定加入二维码指向 `/join`，不直接引用动态微信群或分享者群二维码；图片素材需实际定位、核对，不猜路径。制作阶段的 `show-notes.md`、内部审核备注、源媒体时间、剪辑单和音频继续留在本地 `replays/`；不把整份制作记录复制进公开仓库。

`podcast.md` 是发布文字的长期正式稿，由当期 README 导航，不与本地稿长期双份维护。音频或剪辑版本改变时同步更新时间轴。该 Markdown 归档不改变现有 JSON 字段，也不意味着网站自动展示播客；网站功能变更需另行实施和授权。

## 每期发布元数据与邮件预览

可选文件 `episode-publication.json` 保存网站需要读取的发布信息，不改动 `summary.json` 或 `quote-cards.json` 的结构。网站功能随配套 PR 上线后读取；没有该文件的旧期保持原样。年份、期数从目录取得。

允许的顶层字段为 `podcast`、`newsletter`，均可省略：

| 字段 | 约定 |
| --- | --- |
| `podcast.url` | 已发布的小宇宙单集 HTTPS 地址，主机为 `xiaoyuzhoufm.com` 或 `www.xiaoyuzhoufm.com`，路径为 `/episode/` 加 24 位十六进制单集 ID；不填节目主页或短链 |
| `podcast.title` | 真实单集标题；出现 `podcast` 时和 URL 一起必填 |
| `podcast.durationSeconds` | 可选，实际成品音频时长，正整数秒 |
| `podcast.publishedAt` | 可选，实际发布日期，`YYYY-MM-DD` |
| `newsletter.intro` | 可选，最多 1000 字符，先简短概括本期精华，再带出现场实际讨论的 1–2 个问题，可简短转述而不冒充逐字引语；省略时复用纪要 `overview`，尚未含问句时再接上最多两个本期话题问句 |
| `newsletter.featuredQuoteIndices` | 可选，1–3 个不重复的金句数组位置（从 0 开始），必须指向本期真实卡片；省略时尽量选 3 位不同分享者的原话，人数不足时再从其余卡片补齐 |
| `newsletter.featuredQuoteIndex` | 兼容旧的单条配置，不与 `featuredQuoteIndices` 同时使用；新配置优先使用数组 |

配置示例（本期存在对应卡片时；没有播客时不创建 `podcast` 占位对象）：

```json
{
  "newsletter": {
    "featuredQuoteIndices": [0, 2, 3]
  }
}
```

只记录真实发布信息；没有播客链接时省略该字段，不能用猜测地址或占位值。元数据不包含邮箱、订阅名单、发送记录、密钥或私密制作备注。调整金句顺序后同时检查精选索引。

`podcast.md` 继续保存最终标题、简介与时间轴；网站使用的单集链接、时长和发布日期以 `episode-publication.json` 为唯一结构化来源。已有 Markdown 发布信息可在核实后迁入 JSON，并改成指向该文件，避免长期双份维护。内容制作不要求每期有播客。

完整流程优先制作并发布播客，总结、金句与邮件导语可同时根据逐字稿整理；发布后回填本文件，核对详情页与邮件预览。更新 `newsletter` 时保留 `podcast`，回填 `podcast` 时保留 `newsletter`。详情页与邮件预览读取同一个真实播客链接，手动输入仅作补漏。

网站组织者可从本期详情页打开邮件预览，默认读取 `newsletter.intro` 中先概括精华再带出问题的完整导语、最多 3 条精选原话和真实播客链接。尚未准备正式发送的编辑只保留在当前对话框，关闭不保存；需要长期复用的导语或金句选择在 JSON 中修改并走现有审核流程。预览允许临时填写小宇宙单集链接与标题，可主动发送测试邮件到当前组织者已验证的邮箱；试发不会发送给订阅者。没有链接时提示待补，也可明确选择本期不附播客。临时链接不会写回网站，详情页仍以 JSON 为准。邮件订阅与正式群发属于网站的独立功能，准备正式发送后会保存正式版本和发送记录，核对正文与收件人数并明确确认后才发送给已确认订阅者；打开预览或合入元数据不触发通知。详细操作见 [网站邮件说明](https://github.com/sunling/inspireplanet.cc/blob/main/docs/episode-newsletter.md)。

修改后运行 `python3 scripts/check-content.py`；发布元数据也由该命令校验。
