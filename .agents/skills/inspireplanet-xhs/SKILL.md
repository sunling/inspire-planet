# Inspire Planet 小红书

## 目标

把某期会议里**一位分享者的一段真实经历**，做成一篇可以在小红书发布的图文（图片合集）。

一期会议通常有多位分享者，但**不必都发**：每期挑值得单独发的 1–2 位，每篇只讲一个人的一件事。

## 选题与排期

- **不要求覆盖每一位分享者**；一期只挑值得单独发的 1–2 位，其余不写进来；
- **各渠道独立挑人**：小红书、视频号、公众号可以各挑不同的人，不要为了“公平”把所有人都塞进去；
- 挑选标准：这件事能不能自成一件事、有没有具体场景、脱离上下文能不能读懂；
- 发布节奏：同一渠道**每隔一天发一篇**，不要一天连发；顺序写进文件开头的 `## 发布排期`。

```md
## 发布排期
| 顺序 | 篇目 | 建议发布 |
|---|---|---|
| 1 | {分享人} · {题眼} | 第 1 天 |
| 2 | {分享人} · {题眼} | 第 3 天 |
```

## 工作流程

1. **下载逐字稿**：本期目录还没有 `transcript.txt` 时，先走 `inspireplanet-transcript`；
2. **生成 `xhs-{slug}.md`**：读 `transcript.txt`（有 `gzh-{slug}.md` 时优先），一位分享者一个文件；
3. **生成竖版封面**：按「小红书封面」出 `assets/xiaohongshu-cover.jpg`；
4. **手动触发渲染卡片图**：文字定稿后，由用户触发命令出图（见「渲染成图」）；
5. **手动发布**：图片和文案由人随手发到小红书。本流程**不接平台发布自动化**。

## 路径

活动目录：

```text
events/{year}/{YYYYMMDD}-epXX/
```

优先输入：

```text
gzh-{slug}.md
```

备选输入：

```text
transcript.txt
```

输出：

```text
xhs-{slug}.md
```

规则：

- **一位分享者一个文件**：`xhs-{slug}.md`（如 `xhs-liying.md`），一个文件就是一篇；本期只写挑中的那几位；
- 文件开头保留 `## 发布排期`（见「选题与排期」）；
- 已有同名文件时更新原文件，不创建 `xhs-liying-2.md`；换一位分享者就新建对应的 `xhs-{slug}.md`；
- 小红书内容不写进 `gzh-{slug}.md`（公众号材料与文章一起放在那里）。

## 一节的结构

```md
## {分享人} · {一句话题眼}

### 标题候选
1. {year}EP{episode} - ...
2. ...

### 封面副标题候选
- ...

### 图集脚本
#### 第 1 页（封面）
- 左上署名：{year}EP{episode} · {分享人}的分享
- 主标题：
- 副标题：

#### 第 N 页
- 图上大字：
- 小字：
- 图片建议：

### 正文
{约 200–300 字}

### 话题词
#启发星球 #...
```

## 标题与副标题

### 标题候选

- 每条使用 `{year}EP{episode} - ` 前缀，例如 `2026EP39 - `；
- **含前缀、空格、连字符和标点在内，总长度不得超过 22 个字符**；生成后必须逐条计数校验；
- 贴近小红书语感：第一人称、具体困惑、反差或提问；保留真实与克制；
- 不使用“震惊”“一定要看”“彻底改变”等夸张钩子，也不制造原文没有的焦虑或答案。

### 封面副标题候选

- 每条 **5–8 个中文字符**；
- 不加期数前缀，不写长句，不用逗号、句号凑长度；
- 抓住一个动作、变化或矛盾，如“把选择拿回来”，不概括整期内容。

## 图集脚本

- 默认 6–10 页，第 1 页为封面，末页为邀请；
- 每页只给三样：图上大字、小字、图片建议；文字控制在一屏可读；
- **首图落在具体的人与事上**（时间、动作、场景），不放抽象金句或结论；
- 内页走一条叙事弧：处境 → 细节 → 转折 → 一句原声收尾；不并列堆砌金句；
- 末页用一个问题作邀请，落款「启发星球笔记」；
- 图片优先真实照片（当事人提供）；缺照片时按页降级为氛围图或手写摘录卡。

## 署名与授权

- 分享者**已确认同意**把内容发布在社交媒体时，使用真实人名；
- 未确认时，先标注授权需求，并给出一版匿名化改法（"这一期有位伙伴…"并去掉可识别细节）；
- 不替分享者补结论、不改写立场、不把犹豫改写成坚定。

## 小红书封面

- 优先 `3:4` 竖版，成品 1080×1440；
- 顶部或角落保留清晰期数 `{year}EP{episode}`，主体文字只放一个 5–8 字副标题；
- 期数和副标题必须分别准确呈现，不加入长标题或额外解释文字；
- 图片只放这两组文字，其余靠画面承担；
- 成品路径：本期小红书只有一篇时用 `assets/xiaohongshu-cover.jpg`，多篇时用 `assets/xiaohongshu-cover-{slug}.jpg`；
- 与公众号封面分别构图，不把横版机械裁切成竖版，也不共用最终副标题。

**设计原则、JPEG 保存规范和出图流程见 `../inspireplanet/references/cover-design.md`**，本文件不重复。

## 渲染成图

- 定稿后由用户手动触发一条命令，直接从 `xhs-{slug}.md` 出图（也支持逐页 JSON）：

```bash
python3 scripts/render-cards.py events/{year}/{YYYYMMDD}-epXX/xhs-{slug}.md out_dir/
```

- 渲染样式：暖纸摘录风，无需浏览器；大字默认马善政毛笔楷书（可用 `- 大字字体：kai|klee` 或 JSON 的 `big_font` 切换），小字用霞鹜文楷；页标题里含"原声"的页自动用深色主题（也可写 `- 主题：dark`）；字体首次运行自动下载；
- **卡片图不保存进仓库**：仓库只保留 `xhs-{slug}.md`（图上的文字）。图片是产物，随时可以重渲。
- 需要把一位分享者的**完整分享稿**做成可连续阅读的多页文字卡时，改用 `scripts/text-cards/render.py`（分页 Markdown 输入，启发星球橙主题）；用法与字段见 `scripts/text-cards/README.md`。

## 边界

- 所有事实、人物经历必须来自 `gzh-{slug}.md` / `transcript.txt`，不虚构现场；
- 首图必须落在具体的人与事上，不使用抽象金句；
- 不制造冲突、不夸大结论、不写喊话式口号；
- 生成内容与真实发布分开：**本流程不做平台发布自动化**，发布由人手动完成；

## 完成后的回复

简短说明：

1. 使用的输入（recap 还是 transcript）；
2. 创建或更新的 `xhs-{slug}.md` 路径、本期挑了谁（以及为什么没写其他人）、建议的发布顺序；
3. 推荐的首选标题与封面副标题；
4. 哪些授权、素材或事实仍需确认。
