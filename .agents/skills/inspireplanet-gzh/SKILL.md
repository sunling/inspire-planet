# Inspire Planet 公众号

## 目标

把某期会议里**一位分享者的一件事**，写成一篇**独立成立、能被更多人看见**的公众号文章，并把发布它所需的东西一并备齐：标题、摘要、横版封面。

目标是让**分享本身被看见**，不是记录一场会议。一期有几位分享者时，产出一期多篇；不把所有人的内容压进一篇长文。

本期的索引与发布面板 `index.md`（本期索引、发布排期、封面配置、发布备注）由总控 `inspireplanet` 负责，本 Skill 不产出。

## 结构与长度

- `gzh-{slug}.md`：**分享文章**（约 800–2000 字），一篇只讲一个人的一件事，独立成篇；文件名用分享者英文小写 slug，如 `gzh-liying.md`、`gzh-sunling.md`；
- **一期通常只有 1–2 篇，不是每位分享者一篇**；只有一位撑得住时就只写一篇；
- **能不能成篇的判断**：假设读者只看到标题点进来，能不能读到三段有画面的内容？不能，就别单独成篇——把它交回总控，收进 `index.md` 的「这一期还聊到」；
- 长度由内容决定，不设硬下限；内容撑得住就写足。写不到 800 字，通常说明它还不该单独成篇；
- 不把不同人的分享硬压进一篇；也不为了凑一个统一主题而强行归并。

## 路径

event 目录：

```text
events/{year}/{YYYYMMDD}-epXX/
```

默认输入：

```text
transcript.txt
```

输出：

```text
gzh-{slug}.md
assets/recap-cover.jpg
```

规则：

- **一位分享者一个文件**：`gzh-{slug}.md`，一个文件就是一篇；本期只写挑中的那几位；
- 已有同名文件时更新原文件，不创建 `gzh-liying-2.md`；换一位分享者就新建对应的 `gzh-{slug}.md`；
- 只创建真实需要的文件，不补空目录或占位产物。

## 文件结构（`gzh-{slug}.md`）

**文章在前，发布信息块在后**——文件顶部保持干净，正文可以直接整段粘进公众号编辑器。

```md
# EPXX｜{名字}：{这件事或这个问题}

开头 2–3 句直接进入场景或问题——不写“这一期某某分享了……”。

正文：具体经历、关键观点、必要回应；靠细节和原话推进，不靠小标题。

结尾停在事情本身，不喊口号、不硬加结论。

---

{1–2 句克制的邀请}

<!-- 发布时插入固定图片：启发星球·加入微信社群二维码 -->

---

## 发布信息

- 标题：EPXX｜{名字}：{...}
- 备选标题：
  1. ...
  2. ...
- 摘要：{120 字以内}
```

发布信息块是**这篇的发布材料**，不是文章的一部分：粘正文到编辑器时不要一起带走。

## 公众号标题

- 可以保留较完整的问题、关系和思考转折，长度不必迁就短内容平台；
- 自然、准确、有阅读入口，不制造冲突，不写知识博主式结论；
- 默认沿用分享文章里最真实的核心问题或张力；判断标准是**不看这场会议的人会不会愿意点开**；
- 每篇给 2 个自然、不标题党的备选标题。

## 摘要

- 每篇一个 120 字以内的摘要；
- 准确概括这篇文章，不用“这一次我们聊了很多”等空话；
- 不新增文章正文没有支持的事实。

## 文末行动入口

每篇分享文章在正文自然结束后，用分隔线隔开并保留一个克制的行动入口：

1. 用 1–2 句话邀请读者参加线上会议、加入微信群或带着自己的经历来分享；
2. 紧接着插入固定的“启发星球·加入微信社群”二维码图片；
3. 图片承担主要行动说明，文字不要重复罗列图片上已经展示的全部参与方式；
4. 二维码图片必须使用用户确认的原图，不重新绘制、不生成近似二维码，也不从截图中猜测链接；
5. 图片尚未存入仓库时，用 HTML 注释标明发布插入位：

```md
<!-- 发布时插入固定图片：启发星球·加入微信社群二维码 -->
```

行动入口只在 `gzh-{slug}.md` 里出现一次。`index.md` 是仓库内材料、不对外发布，因此不再承担二维码插入位。

固定行动入口与动态运营信息分开处理：固定图片可以每期复用；下一期日期、会议平台、会议 ID 和临时活动仍按 `current.md` 的验证规则处理。不要因为有固定二维码图片，就补写未经确认的时间或会议信息。

## 公众号横版封面

尺寸与构图：

- 适配公众号横版头图，优先约 `2.35:1`；宽度 ≥1920px；
- 每篇一个封面（一期两篇就是两张），副标题取自本篇的核心变化或动作；
- 成品路径：本期只有一篇时用 `assets/recap-cover.jpg`，一期多篇时用 `assets/recap-cover-{slug}.jpg`；默认只交付带字封面，不生成无字版本。

**设计原则、JPEG 保存规范和出图流程见 `../inspireplanet/references/cover-design.md`**，本文件不重复。

最终封面配置写回总控负责的 `index.md`（见下节）。若 `index.md` 还不存在，按下面这个最小格式创建，只写封面配置，不补其他内容：

```md
# EPXX｜本期索引

## 公众号封面配置

### {slug}（`gzh-{slug}.md`）
- 最终副标题：
- 视觉命题：
- 生成提示词：
- 成品路径：assets/recap-cover.jpg
```

已有 `index.md` 时只更新「公众号封面配置」里对应的那一篇，不覆盖索引正文、发布排期、发布备注或其他篇的配置。不把封面配置追加到文章正文里。

## 开始前读取与 Loop

- 开始前读取 `AGENTS.md`；
- 需要活动时间、会议平台、加入方式或邀请语时，读取 `current.md`；
- 稳定的新偏好写入同目录的 `LEARNINGS.md`；典型改写样本写入 `EXAMPLES.md`；
- 不因一次生成自动更新这些文件。

## 严格边界

- 所有事实、故事、人物观点和资源都必须来自转写或可追溯材料；
- 只做必要整理，不改变原意，不拔高成鸡汤；
- 不从个人分享稿或会后日记补充会议事实；
- 涉及私人信息时删除可识别细节；
- 活动时间、会议 ID、加入方式和下一期信息都属于可能变化的运营信息，不写死在 Skill 中；
- `current.md` 中只有带验证状态、仍然有效的信息可以复用；`status: needs-verification` 时不能把其中待确认内容写进新稿；
- 分享文章是唯一对外发布的文件：标题、摘要、封面都必须与正文一致，不能出现正文没有的内容。

## 参会状态判断

孙玲是否真实参会，会直接影响文章能否使用现场第一人称。不要仅凭转写前 30 行判断。

按以下顺序确认：

1. 先查看当前 event 中是否有明确记录的主持人、参会者或活动说明；
2. 检查转写中的说话人列表、主持开场、互动和孙玲实际发言；
3. 必要时搜索整份 transcript 中可确认的发言标识，而不是只看开头；
4. 用户已明确说明参会状态时，以用户说明为准；
5. 仍无法确认时，不假装在场，采用中性第三人称或明确写“根据会议转写整理”。

判断结果：

- **确认参会**：可以使用真实现场第一人称；
- **确认未参会**：必须写成会后阅读和整理转写的视角；
- **无法确认**：不写具体身体状态、位置或“我在现场发现”，并在完成反馈中说明待确认。

## 工作流程

1. 确认 event、日期、期数、输入 transcript 和参会状态；
2. 阅读完整转写并按发言人整理：具体经历、核心主题、关键判断、必要互动和真实行动；
3. 判断哪几位能独立成篇（见「结构与长度」），确定本篇写谁；
4. 根据参会状态和真实材料，按下方“导语选择”写导语；
5. 每位核心分享者保留：一个具体场景或经历、2–4 个关键观点、一句真正推动主题的互动回应；
6. 资源放回对应分享者段落，不另建冗长资源清单；
7. 按「结构与长度」写文章 800–2000 字；删掉寒暄、重复和旁枝，不硬凑；
8. 正文结尾加入行动入口和二维码图片插入位；
9. 在文件末尾写「发布信息」：标题、2 个备选标题、120 字以内摘要；
10. 生成该篇的公众号横版封面，按 `../inspireplanet/references/cover-design.md` 出图并存 JPEG；
11. 把最终封面配置写回 `index.md` 的「公众号封面配置」；
12. 下一期预告、会议时间、会议 ID 或其他动态加入方式，按“用户当前说明 → 当前 event → `current.md` 中仍有效的信息”的顺序读取；找不到时省略或标记待确认；
13. 用户要求修改已有文章时，优先局部修改，并回到转写核对事实。

## 导语选择

孙玲真实参会时，不固定套用一种开头。按转写中最有力量的真实入口依次选择：

1. **现场瞬间**：有一句话、一个停顿或一次意外真正推动了讨论时，从那个瞬间进入；
2. **真实问题**：全场反复靠近同一个问题、但没有统一答案时，直接提出这个问题；
3. **主理人观察**：分享看似分散时，写出孙玲在倾听中发现的隐约连接；
4. **理解变化**：孙玲原来的判断在会议中确实发生变化时，从“我原来以为……”进入；
5. **开场状态**：以上入口都不明显时，才使用当时的位置、身体状态、环境或开场动作。

导语通常完成三件事：让读者进入真实现场，交代孙玲当时如何在场，并留下一个值得继续阅读的问题或连接。主题应从现场和分享中自然出现，不要提前替所有人总结结论。

不要每期机械重复日期、北京时间、西雅图时间、天气或“这一期内容跨度很大”。只有这些信息真正影响现场、理解或叙事时才保留。不要为了制造统一主题，强行把不同分享归到同一个答案下。

孙玲未参会或参会状态无法确认时，不使用现场第一人称，也不假装主题在现场被自己发现。

## 分享文章的开头

从这位分享者最有力量的真实入口进入：一个瞬间、一个具体场景、或一个真实问题。不要用“这一期”“我们聊到了”这类纪要式开场。

正文不做逐字会议纪要，也不把每个人的每句话都收进去。

## 完成后的回复

简短说明：

1. 写入或更新的 `gzh-{slug}.md` 路径、每篇字数，以及本期选了谁、为什么没写其他人；
2. 每篇的标题、备选标题与摘要；
3. 参会状态及判断依据；
4. 封面成品路径、最终副标题与视觉命题；
5. 哪些活动时间、加入方式、事实或隐私仍需确认。
