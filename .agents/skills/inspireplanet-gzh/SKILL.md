# Inspire Planet 公众号

## 目标

把一位分享者的一件事，写成一篇不看会议也能读进去的公众号文章，并备齐标题、摘要和横版封面脚本；用户确认后生成封面。

## 选题与篇幅

- 能独立成篇的就写，几篇是几篇；
- 判断：读者只看到标题点进来，能不能读到三段有画面的内容？不能，就不单独成篇；
- 约 800–2000 字，长度由内容决定；写不到 800 字，通常说明还不该单独成篇；
- 一篇只写一个人，不把不同人的分享硬压进一篇。

## 路径

```text
events/{year}/{YYYYMMDD}-epXX/
  transcript.txt           输入
  gzh-{slug}.md            输出，一位分享者一个文件
  assets/cover-configs.md         公众号横版封面的配置与设计信息
  assets/recap-cover.jpg   横版封面；一期多篇时用 recap-cover-{slug}.jpg
```

已有同名文件时更新原文件，不新建 `gzh-{slug}-2.md`。

## 文件结构

文章在前、发布信息在后，正文可以整段粘进公众号编辑器：

```md
# 2026EPXX｜{名字}：{这件事或这个问题}

**口述**：{名字}　**整理**：启发星球

{开头正文}

## {简短小标题}

{正文；在自然转折处安排 1–2 个小标题}

---

{1–2 句克制的邀请}

<!-- 发布时插入固定图片：启发星球·加入微信社群二维码 -->

---

## 发布信息

- 标题：EPXX｜{名字}：{...}
- 备选标题：
  1. ...
  2. ...
- 摘要：{120 字以内}
- 作者栏：{名字}
- 封面：`assets/recap-cover.jpg`（计划路径，待确认后渲染）
- 发布前：待 {名字} 本人过目
```

## 口述体

用分享者第一人称写，像分享者自己在讲；作者栏填分享者的名字。

- “我”只能是这位分享者，整理者不出现在正文里；一篇只有一个“我”；
- 其他人进入文章时用名字；同一段出现第二个人之后，不再用裸的“她/他”，改用名字或省略主语；
- 别人的话用直接引语，或“李影问我……”这样转述；
- 所有事实和原话都要能在转写里找到：口头重复和语气词可以删，意思和情绪强度不能加，分享者没说出口的感受不写；
- 口语整理成可读的书面口语，保留分享者自己的用词（如“记忆的考古”“影分身”）；
- 以本人名义发布，**发布前必须给本人过目**；文中涉及的其他人和家人，也要经当事人确认；
- 分享者不愿署名、或不方便以本人名义发布时，改用第三人称：删去口述行，作者栏填“启发星球”，每段首句用名字，同样遵守代词规则。

## 开头与正文

- 以“我”从最有力量的真实入口进入：一个瞬间、一个具体场景，或一个分享者反复靠近的问题；
- 不用“这一期”“今天我想分享”“大家好”开场；日期、时区、天气只在影响叙事时保留；
- 保留一个具体经历、2–4 个关键观点、一句真正推动主题的互动；删掉寒暄、重复和旁枝；
- 书、节目等资源放回提到它的段落，写完整名称，不另列清单；
- 正文加 1–2 个简短的二级小标题，放在经历或理解的自然转折处，用具体、贴近分享者口吻的短语，不写口号或编辑总结；叙事仍靠细节和原话推进；
- 结尾停在分享者自己落到的地方，不喊口号、不替人升华；
- 涉及私人信息时删去可识别细节。

## 标题与摘要

- 标题沿用文章里最真实的核心问题或张力，标准是不看这场会议的人愿不愿意点开；不制造冲突，不写知识博主式结论；
- 备选标题 2 个，同样自然、不标题党；
- 摘要 120 字以内，准确概括本篇，不用“这一次我们聊了很多”这类空话；
- 标题、摘要、封面都不能出现正文没有的内容。

## 文末邀请

- 正文结束后用分隔线隔开，写 1–2 句克制的邀请（参加线上会议、加入微信群或带着自己的经历来分享），不重复二维码图上已有的参与方式；
- 二维码只用用户确认的原图，不重绘、不生成近似图、不从截图猜链接；图片未入库时保留模板里的 HTML 注释；
- 下一期日期、会议 ID 等动态信息按“用户当前说明 → 本期资料 → `current.md` 中已验证的信息”读取；`status: needs-verification` 的内容不写，找不到就不写。

## 横版封面

- 每篇一张，约 `2.35:1`，宽 ≥1920px；
- 只放 6–14 字短副标题，取自本篇核心变化或动作，不重复发布标题；
- 默认 HTML/CSS 渲染；生成配置时独立选择布局 `layout`（`collage` 拼贴、`editorial` 杂志排版、`signal` 大字海报）与配色 `theme`（`collage`、`pop`、`garden`、`blueprint`、`night`），随机均衡分配后把具体组合写入配置，再交用户确认；完整的 `cover-config` JSON、副标题和视觉命题统一写入本期 `assets/cover-configs.md`，按公众号篇目分节，不写入文章；渲染方法见 `scripts/covers/README.md`；
- 设计原则、出图流程和 JPEG 规范见 `../inspireplanet/references/cover-design.md`；
- 本篇「发布信息」的封面一行只保留成品路径，不附副标题、视觉命题或封面配置。修改已有稿件时先把封面配置及设计信息移入 `assets/cover-configs.md`，再移除稿件中的配置块。

## 工作流程

1. 确认 event、期数和 `transcript.txt`；读同目录 `LEARNINGS.md`、`EXAMPLES.md`；
2. 通读转写，按发言人整理经历、观点和互动，判断哪几位能独立成篇；
3. 逐篇用口述体写正文，在自然转折处加 1–2 个简短小标题，再加文末邀请；
4. 通读查代词：每个“她/他”只能指向一个人，不能就改成名字或省略主语；
5. 写「发布信息」；
6. 内容完成后更新 `assets/cover-configs.md`；整期生成时由总控在全部内容完成后统一汇总。发布信息中标明计划封面路径及待确认、待渲染状态；检查文章未保留封面配置；
7. 交付文章与封面脚本，在本期 README 的制作流程第 3 步提供配置链接、使用本期真实路径的渲染命令和确认后出图的 prompt；已有成品需覆盖时说明 `--force`。用户明确确认后才渲染封面、存 JPEG，再更新制作状态；发布授权另行记录；
8. 修改已有文章时局部改，并回到转写核对。

稳定的新偏好写进 `LEARNINGS.md`，典型改写样本写进 `EXAMPLES.md`；用户明确要求复盘时才更新。

## 完成后的回复

1. 每篇的路径、字数；写了谁，没写谁及原因；
2. 每篇的标题、备选标题、摘要；
3. 封面脚本路径、副标题、视觉命题及待确认／已渲染状态；成品已生成时提供实际路径；
4. 发布前需要谁过目，哪些事实、授权、时间或隐私仍需确认。
