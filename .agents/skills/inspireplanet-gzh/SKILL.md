# Inspire Planet 公众号

## 目标

把一位分享者的一件事，写成一篇不看会议也能读进去的公众号文章，并备齐标题、摘要；根据文章直接用 AI 生成有主题、有画面关系的横版封面。

## 选题与篇幅

- 能独立成篇的就写，几篇是几篇；
- 判断：读者只看到标题点进来，能不能读到三段有画面的内容？不能，就不单独成篇；
- 优先写有场景与层次的完整故事，参考下方信息密度要求；材料不足时减少选题，不用空话拉长；
- 一篇只写一个人，不把不同人的分享硬压进一篇。

## 信息密度与忠实度（必须检查）

- 默认目标为 **1200–2200 个中文字符的正文**（不含发布信息、导航和模板）；具体由原始分享的内容密度决定，不把数字当硬性扩写指标。若材料支撑不足 800 字，不靠空话补足：重新判断是否独立成篇，必要时不成篇并说明原因。
- 公众号不是摘要或会议纪要。写作前先从转写提取一份只用于工作过程的「素材骨架」：**起因/现场 → 人物正在做什么 → 至少 2 个具体细节或原话 → 当时的困惑或矛盾 → 想法如何变化 → 现场追问与仍未解决的部分**。与核心主题有关的具体细节优先于概括句。
- 每个核心场景写出「事情怎么发生、人物做了或说了什么、当时如何理解、后来又怎么理解」。例如不是仅写“因为看视频而自责”，而要保留当天还做过哪些自己喜欢的事情，以及自责与这些经历之间的反差；所有补充必须来自转写。
- 原话的语气、迟疑和未完成的探索是内容的一部分。**不能把提问写成结论、把多方讨论压缩成“大家都赞同”**。保留 1–2 段真正推动理解的现场问答，明确说话者；无相关讨论时不强求。
- 优先保留足以改变读者理解的细节，删掉口头重复、偏题闲聊，而不是把每段压成一句中心思想；不要新增场景、心理活动、时间线或漂亮但未经说出的顿悟。
- 初稿完成后反查转写：逐段标出依据（工作过程即可，不写进正文），问“未参会的人能否看见发生的事？是否保留发言者真正的复杂性？”再统计正文长度。**不足预期先回原文寻找遗漏，不做同义反复的灌水**。
- 结构随故事决定，可在自然转折处使用 2–4 个小标题；每一节至少承担一个新的场景、具体发展或思考层次，不机械套固定三段式。

## 路径

```text
events/{year}/{YYYYMMDD}-epXX/
  transcript.txt           输入
  gzh-{slug}.md            输出，一位分享者一个文件
  assets/cover-prompts.md   每篇公众号封面的文案、视觉意图与实际 AI 提示词
  （AI 封面直接交付，不提交生成图片）
```

已有同名文件时更新原文件，不新建 `gzh-{slug}-2.md`。

## 文件结构

文章在前、发布信息在后，正文可以整段粘进公众号编辑器：

```md
# 2026EPXX｜{名字}：{这件事或这个问题}

**口述**：{名字}　**整理**：启发星球

{开头正文}

## {简短小标题}

{正文；在自然转折处安排 1–2 个小标题}

---

{1–2 句克制的邀请}

<!-- 发布时插入固定图片：启发星球·加入微信社群二维码 -->

---

## 发布信息

- 标题：EPXX｜{名字}：{...}
- 备选标题：
  1. ...

- 摘要：{120 字以内}
- 作者栏：{名字}

```

## 口述体

用分享者第一人称写，像分享者自己在讲；作者栏填分享者的名字。

- “我”只能是这位分享者，整理者不出现在正文里；一篇只有一个“我”；
- 其他人进入文章时用名字；同一段出现第二个人之后，不再用裸的“她/他”，改用名字或省略主语；
- 别人的话用直接引语，或“李影问我……”这样转述；
- 所有事实和原话都要能在转写里找到：口头重复和语气词可以删，意思和情绪强度不能加，分享者没说出口的感受不写；
- 口语整理成可读的书面口语，保留分享者自己的用词（如“记忆的考古”“影分身”）；
- 以本人名义发布，**发布前必须给本人过目**；文中涉及的其他人和家人，也要经当事人确认；
- 分享者不愿署名、或不方便以本人名义发布时，改用第三人称：删去口述行，作者栏填“启发星球”，每段首句用名字，同样遵守代词规则。

## 开头与正文

- 以“我”从最有力量的真实入口进入：一个瞬间、一个具体场景，或一个分享者反复靠近的问题；
- 不用“这一期”“今天我想分享”“大家好”开场；日期、时区、天气只在影响叙事时保留；
- 保留一个具体经历、2–4 个关键观点、一句真正推动主题的互动；删掉寒暄、重复和旁枝；
- 书、节目等资源放回提到它的段落，写完整名称，不另列清单；
- 正文可加 2–4 个简短的二级小标题，放在经历或理解的自然转折处，用具体、贴近分享者口吻的短语，不写口号或编辑总结；叙事仍靠细节和原话推进；
- 结尾停在分享者自己落到的地方，不喊口号、不替人升华；
- 涉及私人信息时删去可识别细节。

## 标题与摘要

- 标题沿用文章里最真实的核心问题或张力，标准是不看这场会议的人愿不愿意点开；不制造冲突，不写知识博主式结论；
- 备选标题 2 个，同样自然、不标题党；
- 摘要 120 字以内，准确概括本篇，不用“这一次我们聊了很多”这类空话；
- 标题、摘要、封面都不能出现正文没有的内容。

## 文末邀请

- 正文结束后用分隔线隔开，写 1–2 句克制的邀请（参加线上会议、加入微信群或带着自己的经历来分享），不重复二维码图上已有的参与方式；
- 二维码只用用户确认的原图，不重绘、不生成近似图、不从截图猜链接；图片未入库时保留模板里的 HTML 注释；
- 下一期日期、会议 ID 等动态信息按“用户当前说明 → 本期资料 → `current.md` 中已验证的信息”读取；`status: needs-verification` 的内容不写，找不到就不写。

## AI 横版封面

- 每篇一张。通读最终文章，从本篇独有的经历、变化或问题构图；不要仅根据标题或通用“成长、阅读、对话”标签出图。
- 直接调用当前环境的 AI 图像生成工具（如 `image_gen`），默认使用内置生图工具；不要写 HTML/CSS、SVG、截图脚本或选择固定卡片模板来代替生图，也不要自行搭建 API runner。工具不可用时如实说明，只交付提示词，不声称已出图。
- 用户要求“文章和封面一起生成”或“根据文案生成封面”时，完成文章后直接生成，不再增加一轮封面配置确认。用户明确要求先给方案、只写稿或暂不出图时，按指定范围停在文字阶段。生成图片不等于获得发布授权。
- 默认宽横版约 2.35:1，目标宽度 ≥1920px，按当前工具实际支持的尺寸生成。重要文字与主体留出裁切安全边距；核对实际输出后再报告尺寸，不虚报精确像素。
- 带字成品只放 6–14 字短副标题，补充文章标题；在提示词中逐字列明准确文案。不要把全文标题、摘要和信息卡塞进画面，不加 Logo、水印、二维码或伪文字。
- 风格和配色由文章决定，可采用插画、象征性叙事、编辑视觉或其他合适手法；不要固定拼贴、双卡片、连线或随机配色。保留文章自己的复杂性，不把普通生活包装成励志海报。
- 不生成可识别真人或伪造真实会议现场；使用用户提供的照片时核对使用许可。具体设计与检查见 `../inspireplanet/references/cover-design.md`。
- 在本期 `assets/cover-prompts.md` 按篇记录对应文章链接、准确副标题、视觉意图及实际提示词，便于修改或重新生成。不要再新建 `cover-config` JSON、`layout/theme/tiles` 等程序渲染配置；历史配置仅作旧素材参考。
- 出图后检查中文字、主题关系、裁切与构图。发现错字、伪字或关键主体缺失时，用 AI 工具定向修改或重生成；不交付未经检查的图片。
- 直接展示生成结果，沿用当前工具的交付机制；生成图片不提交 Git，不声称图片位于并不存在的 Actions Artifact。文件导出、JPEG 压缩或指定尺寸只在确有发布需求且工具支持时处理，并说明实际格式。

## 工作流程

1. 确认 event、期数和 `transcript.txt`；读同目录 `LEARNINGS.md`、`EXAMPLES.md`。
2. 通读转写，按发言人整理经历、观点和互动，判断哪些分享能独立成篇。
3. 逐篇用口述体写正文，在自然转折处安排小标题，再加文末邀请。
4. 核对事实、原话、代词、正文长度和本人审核事项，完成标题、摘要等发布信息。
5. 从每篇文章提取准确的短副标题与视觉意图，在 `assets/cover-prompts.md` 保存提示词；仅在本期 README 链接该文件，不重复正文或提示词。
6. 按用户本次请求直接用 AI 生成封面，或在明确要求暂不出图时只交提示词。每篇单独生成并检查，不制作一张包含多篇封面的拼图。
7. 交付文章与已生成图片，明确尚未生成的项和实际问题；发布前仍须分享者本人及文中涉及的当事人审核授权。
8. 修改已有文章时回到转写核对；重做封面时只更新相关篇目的提示词与图片，不重写无关正文。

稳定的新偏好写进 `LEARNINGS.md`，典型改写样本写进 `EXAMPLES.md`；用户明确要求复盘时才更新。

## 完成后的回复

- 给出每篇文章的路径、正文大致字数、标题、摘要，以及选题取舍。
- 给出封面准确文案、提示词路径和实际生成结果；未出图时明确原因，不将提示词或计划路径当作成品。
- 列出发布前需要谁过目，以及尚待核对的事实、隐私与授权。
