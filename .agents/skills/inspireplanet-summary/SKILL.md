# Inspire Planet Episode Summary

让没有参会的人读到一段具体的交流，让参加过的人重新找到当时想继续聊的地方。以真实发生的事、人的不同处境和交流的推进组织内容。

## 输入与交付

先读仓库 `README.md`、`current.md`、目标期 `README.md` 的发布备注和完整 `transcript.txt`。已有 `gzh-*.md`、`quote-cards.json` 与旧纪要只辅助理解；事实与引语回查转写。

```text
events/{year}/{YYYYMMDD}-epXX/
  transcript.txt      输入，保持原样
  README.md           输入及导航、发布备注
  gzh-*.md            可选参考
  quote-cards.json    可选参考，不随本任务另造一套金句
  podcast.md         如有，读取已确认的播客发布文字
  episode-publication.json  如有，保留已回填的播客链接；维护邮件问题导语
  summary.json        输出，网站回顾的兼容 JSON
  group-message.md    输出，可直接复制到群里的正文
```

完整会后流程先制作、试听并发布小宇宙播客，回填 `episode-publication.json` 中的真实链接后，再接手回顾和金句。先读该文件及 `podcast.md`；更新邮件导语时合并现有字段，不能覆盖已回填的 `podcast`。详情页与邮件预览共用该结构化链接，不解析 Markdown 或猜地址。用户单独要求文字、播客暂缓时仍可先出文字，缺失链接之后补。保留现有 `summary.json` 和金句 JSON 契约，不把音频字段加进纪要。

默认生成回顾与群消息；用户只要求其中一项时只制作该项。更新当期 README 导航，保持正文各有一份，不把群消息复制成多份长期稿。修改 skill 时同时核对 `agents/openai.yaml`。

## 编辑方法

1. **先找现场片段。** 从转写找：谁遇到什么事，卡在哪里，谁接着追问、补充或提出不同经验。先记下源时间区间，便于核对；不把时间戳放进读者正文。
2. **按真实问题或经历分段。** 通常选 2–5 段，根据材料增减。可围绕一位分享者，也可包含几个人的来回；不按人数平均分配篇幅，不为了凑栏目把同一段交流拆碎。必要的背景和限制跟随观点，不把不同处境合成统一答案。
3. **先写可独立阅读的短片段。** 让 `context` 的前两三句话呈现具体事、问题或不同看法。即使读者没有展开，也能读懂这段交流的由来。`quote` 优先选自然、具体、值得记住的原话，不强行提炼金句。
4. **再保留展开后的过程。** 用 `keyPoints` 保存具体经历、行动、原有判断、尝试或变化；用 `discussion` 写谁怎样接话、追问又把讨论带向哪里。按材料写自然段，不强求每段同样长、同样条数或都有转折。无需给每段补一个正面结论。
5. **回头写标题和开场。** 标题用具体场景或真实问题；问题句只在合适时用。导语选一两个入口，不逐个点名报告谁分享了什么，也不套“自我接纳、持续成长、生命力”等概念串。
6. **最后选群消息的一个片段。** 从完整转写核对，优先选能在群里直接读懂、有人接话或出现不同看法的短交流。群消息的选择不必与回顾标题或第一段相同。

## 写法与事实边界

- 写得出事：保留一个动作、处境、犹豫或限制。例如保留“八百米间歇跑只能跟一圈就停下来，第三轮放慢速度跑完”，不只写“在运动中突破自我”。
- 写得出人：明确谁说的、谁提出了另一种看法。保留“还没找到”“不敢迈出第一步”“这次跟不上”等未完成状态。
- 写得出过程：有真实回应才写交流推进。独白、平行分享就按其原貌呈现；不把前后相邻的发言编成因果或问答，不补造笑声、沉默、激动、现场气氛、顿悟或达成共识。
- 分清引用与转述。引号内只放可回查的原话，可去口头重复、修标点；重写的表达用具名转述，不包装成引语。书中话语保留阅读来源，不算分享者原创。
- 不写“这段讨论让我们明白……”式共同结论；个人体验不写成普遍规律。发现两个人观点接近，也保留各自前提。
- 不从个人日记或私人分享稿补会议事实。遵守当期署名、匿名、第三方信息与公开边界；不把未核实的旁枝写成吸引人的冲突。
- 字数仅作参考，以完整、具体和不重复为准。不给每个人强配三条“收获”，不让每段都走同一套起承转合。

## summary.json：保留网站字段

遵循 [内容数据约定](../../../events/data-contract.md)，不新增字段或修改类型来改变写法。输出 UTF-8、2 空格缩进，字段顺序如下：

```json
{
  "episode": "EPXX",
  "date": "YYYY-MM-DD",
  "title": "本期具体场景或值得继续想的问题",
  "overview": "约 60–120 字：从一两处具体交流进入本期，不写全员主题清单",
  "topics": [
    {
      "speaker": "主要分享者署名；确属共同展开时可列多人",
      "title": "这段交流中的具体经历或问题",
      "context": "约 60–140 字：读者不展开也能读懂的场景与问题，不把读下文作为理解前提",
      "keyPoints": [
        "具体过程的一段；数量随材料变化，通常 1–4 段，每段约 50–120 字。先写经历和变化，不加概念小标题凑要点"
      ],
      "quote": "有归属、可回查的代表原话；多人话题时明确这句话是谁说的",
      "discussion": "谁怎样接话、澄清或补充；通常 80–200 字。没有真实回应时用空字符串，不补造问答"
    }
  ],
  "highlights": []
}
```

- `keyPoints` 保持非空字符串数组；`context`、`quote` 保持非空，`discussion` 可为空。核心材料不足时缩小选题或留出待核对事项，不编内容填格式。
- `speaker` 保留主线发言归属；其他人的经历在正文逐一归名。多人话题的 `quote` 加实际说话人，防止误认。
- 将简读场景、展开过程和现场回应分配到对应字段，同一件事不在三个字段完整复述。`highlights` 只留未归入主段的具体片段，没有就用空数组。
- `episode`、`date` 与目录一致；年份由目录确定。修订已有期次时尽量保持话题顺序和原有话题链接含义，调整顺序需在交付说明中指出。


## 邮件导语：摘出本期的 1–2 个问题

整理完整期回顾时，顺带在 `episode-publication.json` 的 `newsletter.intro` 保存一两句话：选本期现场真实提出、追问或展开过的 1–2 个问题，优先保留不同话题里的具体疑问；不做全期内容目录，也不复述会议总结。可以简短转述，不能把改写的问句加引号冒充逐字原话。

从转写核对问题和上下文，保留原来的条件、分歧与未解决状态。不要把普通分享强行改成问题，不套“如何逆袭／你是否也……”等悬念。只有一个合适问题就只写一个；确实没有问题时保留具体经历导语，不为数量编问题。网站的 `overview` 继续服务整期阅读，邮件问题导语独立放在 `newsletter.intro`，不因此改坏回顾开场。

EP42 的写法示例：`自责也是一种方法吗？生活稳定、有秩序，不需要一直认识新人，也可以是很好的状态吗？` 两个问题分别来自孙玲 00:18:37 和抹茶 01:18:19 的提问，属于简短转述，不是两人共同得出的结论。

写入时保留 `podcast`、已配置的精选金句索引及其余合法字段；已有 `newsletter.intro` 有具体编辑取舍时先核对再修改。单独只做群消息时不顺手修改邮件配置。新增文件更新当期 README 导航；生成或合入配置不会自动发送邮件。

## group-message.md：一条消息，一个片段，一个入口

文件只放可复制的群消息正文，不放标题备选、内部评语、时间戳、审核清单、制作进度或文件路径。通常 150–300 字，按内容自然分段。

- 开头直接给一个场景或问题；简短交代它来自哪一期。
- 保留一小段“某人说了什么，另一个人怎样接着说”的过程。缺少互动时选一个完整的具体经历，不硬造另一位回应者。
- 不点链接也能读到有意义的内容，不写成悬念广告，也不摘抄整期目录、罗列全员与全部产物。
- 结尾只留一个已确认的本期回顾链接。来自用户、当期文件或实际核实的页面；不凭已知期数推测网址。缺少链接时先交付无链接正文，在交付说明中列待补项，不把占位符混进可发正文。
- 不同时放周刊、播客、公众号、社群邀请或下一期报名链接。仅当音频确已发布且回顾页确有入口时，才可顺带一句收听提示；不写未经实现的页面功能。
- 不强加“欢迎讨论、欢迎留言、转发支持”等号召。片段本身有自然延续的问题时可留下，不再叠加一个互动任务。
- 不代发群消息。群内发布和公开网页的授权分别核对，准备文案不等于可以发送。

## 交付前核对

1. 回查转写：每个具体细节、引语、说话人、回应关系与变化都有依据。把必要的源时间区间记到当期 README 折叠的编辑核对记录，不放进展示字段或群消息。
2. 连续读一遍：遮住姓名之后，是否仍能辨认每段的具体事？是否只是把“分享了、强调了、体现了”换了措辞？是否把仍在犹豫的人写成已经解决？据此改写。
3. 单读每个 `context` 和整条群消息：不展开、不点链接也能理解；群消息确实只有一个重点和一个入口。
4. 核对字段、目录身份与导航，运行 `python3 scripts/check-content.py`。普通文案调整不改 JSON 契约、网站代码或其他渠道稿。
5. 交付稿件与主要取舍，说明未核实事项；通用 skill 变更使用独立分支与 Draft PR。只在获准公开的材料范围内提交。合入 `main` 会被网站读取，需用户确认；不自动发群或改站点。
