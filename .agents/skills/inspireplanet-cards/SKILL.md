# Inspire Planet Quote Cards

## 路径

活动目录：

```text
events/{year}/{YYYYMMDD}-epXX/
```

输入：

```text
transcript.txt
```

输出：

```text
quote-cards.json
```

早期人工整理材料如存在，保存在：

```text
quote-notes.md
```

## 边界

- 金句、人物、经历和语境必须来自转写。
- 只允许去掉口头语、重复词和补充标点，不新增观点。
- 不把不同人的观点拼成一句。
- 不为了数量制造卡片；按内容密度决定，覆盖主要分享者。
- 卡片真实、纪实、有温度，不写空洞口号。

## JSON 格式

输出纯 JSON 数组，不加 Markdown 代码块。每个对象只包含并按此顺序排列：

```json
{
  "name": "分享者",
  "title": "4–10 字主题",
  "quote": "可追溯的原句或轻整理表达",
  "detail": "这句话出现时的具体经历、处境和会议语境",
  "episode": "EPXX"
}
```

## Detail 写法

`detail` 不是 quote 的一句话释义，而是一段可以独立读懂的微型现场记录。默认约 150–230 个中文字符；内容本身较短时可以略短，但不应为了简洁压缩成 50–80 字的摘要。

一条完整的 `detail` 通常保留三层信息：

1. **具体场景或处境**：分享者当时经历了什么，面对什么限制、关系或真实问题；
2. **发展与转折**：事情如何影响了分享者，后来发生了什么，原有理解在哪里开始松动或变化；
3. **金句语境**：这句话为什么会在这里出现，它回应的是哪段经历或现场追问。

不要求机械分成三句，但不能只改写 quote、概括主题或写成编辑点评。优先保留动作、细节、犹豫、前后反差和分享者自己的理解；不替分享者补结论或给建议。涉及隐私时，删去可识别信息，但尽量保留理解这句话所需的真实处境。

## 工作流程

1. 阅读转写并按发言人分段。
2. 找出观点明确、能独立成句、对理解本期有帮助的表达。
3. 回到上下文确认说话人、事实和真实含义。
4. 为每条 quote 回到前后文，按“具体场景—发展与转折—金句语境”写 `detail`。
5. 生成 JSON 并验证可解析。
6. 检查字段、人物归属、重复卡片、过度改写，以及 `detail` 是否被压缩成一句摘要。

稳定偏好记录在同目录 `LEARNINGS.md`，典型样本记录在 `EXAMPLES.md`；只有用户明确要求复盘时才更新。
