# 启发星球原声短视频

把一位分享者的一件事做成能独立听懂的原声短视频。默认先推荐选段，用户确认后生成初剪、字幕、封面与两平台文案；成片确认和公开授权另行核对。已有选段或样式确认继续有效，不重复询问。

## 输入与本地资料

先读仓库 `README.md`、`current.md`、本期 `transcript.txt` 和 README 的发布备注。会议事实来自本期转写与回放；文章只用于辅助理解，不用个人日记或个人分享稿补造事实。原转写不修改。

用户手动下载回放，默认直接放 `replays/{YYYYMMDD}-epXX.mp4`（也可为音频）；沿用用户实际位置，不要求每期再建源文件夹，不擅自移动。先核对文件、日期、分享者和对应期次，不能只根据文件名判定录制归属。缺回放时请求本地路径，不自动连接腾讯会议或启动公开转写归档。

制作目录建议为 `replays/{YYYYMMDD}-epXX-clips/`；已有目录原地维护。先用 `git check-ignore` 确认忽略规则有效，再写入。回放、识别结果、候选单、剪辑单、字幕、发布文案、图片与视频全部留在本地，不上传识别服务、不放入公开 PR，也不写进公开单期 README。只有另获具体公开授权，才单独整理可公开源稿。

## 选段

- 默认给 3–5 个有价值的候选，材料不足就少给；用户已指定选段时直接继续。
- 每条包含分享者、编辑标题、来源时间、预计时长、选题理由和待核对内容。尚未对齐时明确写“转写定位”，不能冒充视频切点。
- 选择有具体情境、动作、转折或真实问题的完整小故事；不把一句脱离上下文的金句强行成片。
- 一条通常围绕一个人一件事，时长服从表达完整性，不为达到固定秒数灌水或截断保留条件的发言。
- 用户确认选段后才裁切出初剪；选段确认不代表肖像、家人话语或具体成片可公开。

## 原声对齐与剪辑

制作时读 [剪辑单格式与运行说明](references/edit-plan.md)，使用随附本地工具。

1. 用 `scripts/align.py inspect` 读取实际音视频轨、时长和尺寸，提取必要预览。系统播放器打不开时可用 FFmpeg/PyAV 判断，不把框架不兼容直接当作文件损坏。
2. 在候选附近取短窗口做本地识别，得到实际媒体秒数；对照原话，分别核对每段开头、关键句和结尾。录制可能晚开始或含中途删段，不用总时长差推断固定偏移，不把整场偏移套到所有段落。
3. 写 `edit-plan.json`：实际媒体入点／出点、裁切区域、字幕和删减原因。用户确认过的片段才设为 `confirmed: true`。不根据自动识别结果擅自改名、补年份、补书名或扩写观点；拿不准的词回到原声核对，必要时避开不清的短语并说明。
4. 保留原声顺序和自然停顿，可精简口头重复、冗长铺垫及同主题的次要例子；不能通过跨段拼接给分享者制造新的结论。不默认加配音、音乐或虚构现场画面。
5. 裁切区域按该段实际布局选择：有可用人像就保留分享者；只有演示页时保留相关内容，去掉浏览器栏、凭据、无关窗口及其他参与者。布局变化时分段或换模板，不能沿用错误的固定坐标。只有音频时用原声配文字画面，不伪造说话人影像。

`scripts/align.py` 支持局部识别和时间码输出，不会自动判定选题、署名或授权。模型识别、人工核对和实际听审是不同环节，在交付中准确报告完成了哪些。

## 画面、字幕与发布文案

- 默认沿用已确认的 EP41 深色版：1080×1920、整张深绿色底、浅色标题与字幕、暖棕色点缀，原始人像或演示页居中。底部保留原来的排列：标语在上、官网在下、日期靠右，不因更换配色擅自改写文字或更换排列。画面清晰度受原始窗口限制，不能靠放大恢复细节。
- 兼顾平台叠字：底部整组上移，给平台白色发布文案、位置和控件留空间，不另拼一块深色底板。当前模板字幕居中 y=1395，标语 y=1500、官网 y=1550、日期基线 y=1587，y=1660 以下留空。位置仅作为当前模板的起点，手机端仍需按实际文案长度与界面复核，不能当作所有平台通用的固定安全区；模拟平台叠字只用于预览，不烧录进成片。
- 字幕从实际原声对齐，可轻度删除口头重复、补标点；不可把概括性文案当作逐字引语。不清的词在私人核对备注中说明，不把编辑说明烧录进画面。
- 底部只显示简短官网域名。官网、社群入口与统一邀请语从 `current.md` 已确认部分读取；本期内容页使用用户提供或核实过的实际链接，不凭年份／期数推断链接存在。
- 每条分别写小红书、视频号的标题、正文和话题。围绕最终成片，不把被删掉的故事写成片中内容；第一人称必须明确归属分享者。
- 发布标题、正文、话题和备选收尾均用可直接复制的纯文本。链接写为“加入启发星球社群：完整网址”或“阅读本期更多内容：完整网址”，不用 Markdown 链接、加粗、引用块或列表符号；平台话题标签保留。Markdown 只用于稿件分区和内部核对记录，不进入待发布文本。
- 每个平台正文只保留一个主要入口：默认“加入启发星球社群”，需要继续阅读时换成本期更多分享。备选收尾单列，发布时二选一；视频和封面不叠加多个长链接或二维码。

## 导出、检查与交付

用 `scripts/render.py` 从剪辑单导出初剪、SRT、ASS、封面和预览；不覆盖原回放。工具不会替用户授权，也不会提交 Git 或发布到平台。

检查导出的视频尺寸、音视频轨、全片可解码、字幕与声音同步、句首句尾、跳切衔接、音量、标题溢出和手机阅读效果；检查关键帧及每个布局变化处，调整后只重新检查受影响部分。私人成片资料不上传 GitHub Actions。

每条的 `clip-{slug}.md` 放剪辑依据与两平台文案，文末列出需要当事人确认的事实、肖像或公开范围。制作状态与检查结果留在私人目录或交付回复，不写进单期公开 README。

交付给用户可播放的本地视频、封面、文案与字幕链接，说明实际时长、删减取舍、源画面限制和未完成的听审。用户审片后按反馈更新同一份源稿与剪辑单；只有收到明确发布指令才操作外部平台。修改公开源文件后运行 `python3 scripts/check-content.py`。
