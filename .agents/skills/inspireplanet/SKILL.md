# Inspire Planet

把分享者的分享整理出来，让更多人看见。一篇文章围绕一位分享者的一件事，一期可有多篇；不要求每期生成所有交付物。

## 输入与输出

先读仓库 `README.md`、`current.md`、本期真实转写和发布备注。当前渠道为文字→公众号（知乎计划开通）、视频→视频号／小红书、音频→暂时小宇宙；渠道状态以 `current.md` 为准。

```text
events/{year}/{YYYYMMDD}-epXX/
  transcript.txt     原始会议转写
  gzh-{slug}.md      公众号文章，文末维护标题和摘要
  summary.json       网站单期回顾
  group-message.md   一个现场片段与一个本期链接的群消息
  quote-cards.json   金句与周刊数据
  podcast.md        获准公开的播客最终标题、简介、成品时间轴与发布链接（按需）
  README.md          导航、实际可用的命令和发布备注
```

视频切片与播客默认共用一份带声音的本地回放视频，不要求分别下载音频和视频，也不要求用户预先提取音轨；已有纯音频仍可使用。具体音轨检查由对应 skill 完成。

旧图文渲染脚本已清理，历史版本从 Git 查阅，不再创建新图文脚本。短视频与播客的媒体、制作草稿和内部审核资料放在本地被忽略的 `replays/`；播客最终发布文字获准公开后才整理为当期 `podcast.md`，不把内部记录复制入库。

## 路由

- 转写下载／历史补录 → [会议转写说明](../../../docs/meeting-content.md)。已有转写不重复下载；下载会提交公开 main，须先确认该场转写的公开授权，整理请求不等于下载公开授权。
- 公众号文章、标题、摘要 → `inspireplanet-gzh`。知乎计划开通，开通后再明确适配方式，不默认另生成知乎稿。
- 网站回顾与会后群消息 → `inspireplanet-summary`。默认同时生成 `summary.json` 与 `group-message.md`；用户只要其中一项时只做该项。群消息只选一个片段、一个主要入口，不同时堆放多个渠道链接。
- 金句 JSON → `inspireplanet-cards`。网站金句展示与导出继续使用 JSON 数据。
- 小红书／视频号原声短视频及发布文案 → `inspireplanet-clips`。缺少回放时先请求本地素材路径；有素材时先推荐选段，确认后初剪。
- 整期播客、播客音频轻剪及话题时间轴 → `inspireplanet-podcast`。一期一集，默认保留现场开场与道别，不额外添加配音或音乐；本地交付后再审听与确认公开范围，暂时面向小宇宙；获准公开的最终发布文字归档为 `podcast.md`。
- 多项整理 → 只组合用户需要的交付物，按 [内容数据约定](../../../events/data-contract.md) 保持字段与审核边界。

## 完整会后流程的交接

用户要求整期流程时，按以下优先级组织；总流程见 [内容制作说明](../../../docs/content-workflow.md)：

1. **准备两份素材**：同一期带声音的回放视频与逐字稿一起准备，已有素材不重复下载。视频由用户手动下载，转写按会议转写说明手动触发工作流；当前没有一次操作自动下载两者的实现。核对日期、期数、内容及转写公开授权，切片与播客共用该视频。
2. **播客优先，文字同时开始**：用 `inspireplanet-podcast` 轻剪并准备 show notes；同时用 `inspireplanet-summary` 和 `inspireplanet-cards` 根据逐字稿整理会议总结、金句和群消息草稿，不等待播客发布。播客 show notes 使用已核实的本期页和固定加入二维码；页面尚不存在时列待补，不虚构链接。
3. **发布并取得链接**：用户试听、确认具体公开范围后发布小宇宙；代发布需明确指令。在当期 `podcast.md` 回填真实单集链接、实际时长、发布日期和已核实入口。
4. **完成本期详情页**：总结、金句与该期小宇宙单集链接应在同一详情页展示。先核对站点实际读取方式；归档不等于展示。若功能缺失，明确交接站点任务，在获准的站点范围内实施；未获授权或未完成时列为待办，不声称完成。核对页面期次、内容和播客链接正确可用后，群消息仍只保留本期详情页一个入口，不另外堆放播客链接。
5. **公众号文章**：用 `inspireplanet-gzh` 从逐字稿整理能独立成篇的故事，交本人审核。
6. **视频切片**：用 `inspireplanet-clips` 复用同一视频，先推荐选段，用户确认后制作初剪、字幕与两平台文案，再审片。

这不是所有产物都必须串行等待的限制。单项请求直接做该项；播客待发布时继续整理文字，已获准的文字可先上线，发布后再补播客链接。页面上不得出现假链接、占位发布状态或未经核实的收听提示。不自动发群、发布播客或修改站点。

## 内容质量与审核

回看转写中的具体场景、行动、矛盾、变化和追问；公众号按对应 skill 写完整叙事，信息不足时不勉强成篇。纪要与金句保留发言归属和可追溯语境；不从个人日记或个人分享稿补造会议事实。原始转写不随编辑稿润色。

短视频由 clips 负责实际时间对齐、字幕和剪辑，不把文章直接转成原声引语，不把选段确认视为成片或发布授权。官网和社群入口读取 `current.md` 已确认部分。

生成不等于获准公开。当事人确认具体稿件、署名、他人信息及公开范围后再交用户发布；不自动操作外部平台或修改站点。合并到网站读取的 main 前复核授权。

## 单期 README

通用步骤链接 [内容制作说明](../../../docs/content-workflow.md)，稿件导航只链接真实存在的文章、转写与 JSON。不保留指向已清理图文脚本的导航；历史版本通过 Git 查阅。

有实际可用且可公开的本期命令才列命令小节，不再列已退役的图卡命令，不把私人回放路径或制作进度写入公开 README。发布备注保留本期特有的事实、隐私、授权和已确认发布链接；较长溯源记录可折叠。

交付时说明生成了哪些内容、选题取舍与待核对事项。修改后运行 `python3 scripts/check-content.py`。
