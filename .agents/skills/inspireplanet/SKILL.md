# Inspire Planet

## 定位

把分享者的分享整理出来，让更多人看见。默认产出是**一位分享者的一件事**：一期多篇，一篇一个人一件事，不写会议纪要式的长篇汇总。

## 本期目录

```text
events/{year}/{YYYYMMDD}-epXX/
  transcript.txt                会议原始转写
  gzh-{slug}.md                 公众号文章（文末附标题、摘要、封面成品路径）
  xhs-{slug}.md                 小红书图文
  sph-{slug}.md                 视频号图文
  summary.json                  网站单期详情页的分享纪要
  quote-cards.json              金句卡片与周刊数据
  assets/cover-prompts.md        公众号 AI 封面的文案、视觉意图与提示词
  （生成的公众号 JPG 不入库）
  README.md                     本期导航、命令与发布备注
```

`{slug}` 是分享者的英文小写名，一位分享者一个文件，如 `gzh-liying.md`。只创建真实需要的文件。

## 路由

- 逐字稿 / 转写 → GitHub Actions，入口与历史补录见 [下载说明](../../../docs/meeting-content.md)
- 公众号文章 / 标题 / 摘要 / 横版封面 → `inspireplanet-gzh`
- 小红书 / 图集 / 竖版封面 → `inspireplanet-xhs`
- 视频号 → `inspireplanet-sph`
- 网站纪要 / summary.json → `inspireplanet-summary`
- 金句 / 卡片 JSON → `inspireplanet-cards`
- 本期导航 / 命令 / 发布备注 → 本 Skill

完整发布包包含两份 JSON；只生成指定交付物时不扩展范围。字段、期次身份、溯源和审核后同步方式见 [内容数据约定](../../../events/data-contract.md)。生成不等于公开，提交到网站读取的 `main` 分支前核对具体稿件与授权。

## 工作流程

1. **下载与归档**：通过 GitHub Actions 拉取转写并创建公开 Draft PR，人工审核期次与公开范围后归档为本期 `transcript.txt`。已有转写不重复下载；缺少时提供 Actions 入口，等待转写归档或用户提供原稿。触发下载并公开原稿须有用户授权；仅请求整理内容不视为下载公开授权。
2. **生成发布包**：全套包括公众号文章、小红书与视频号各自图文脚本、网站纪要 `summary.json`、金句 `quote-cards.json`，以及公众号 `assets/cover-prompts.md`。只生成用户指定渠道的交付物。先完成文章，再根据每篇内容设计 AI 封面；不创建代码封面配置或随机选择布局。小红书／视频号各篇在脚本中保存主题与第 1 页首图内容。
3. **出图与检查**：公众号按 `inspireplanet-gzh` 直接调用 AI 生图工具；用户要求生成文章和封面时直接执行，明确要求暂不出图时只保存提示词。小红书／视频号仍先确认各页文字、署名、主题与字体，再分别通过 `render-content.yml` 渲染。两条出图路径分别检查，不把公众号 AI 封面交给图卡工作流。
4. **发布**：当事人确认具体稿件、署名及公开范围后，由用户检查图片并发布。不直接操作外部平台。

已确认且未修改的图卡脚本可以直接重渲染；图中文字或视觉命题变化后只重新确认受影响部分。公众号生图直接交付当前工具的结果，不生成或承诺 Actions Artifact。小红书／视频号使用 GitHub Actions 临时 runner，Artifact 保留 1 天；生成图片均不提交 Git。详细步骤见 `docs/rendering.md`。

## 跨平台内容质量门槛

总控在生成发布包时，不能把公众号当作三段式梗概，也不能把图文脚本当作提纲：
1. **先忠实抽取分享的细节**：场景、人物、具体行动、矛盾或犹豫、变化与现场追问。各渠道都要回看转写，公众号稿不是社媒稿唯一可用的信息源。
2. **公众号**：按 `inspireplanet-gzh` 的完整叙事与正文长度自检；不足时先找遗漏的现场细节，若转写支撑不了长文就不勉强成篇。
3. **小红书、视频号**：按各自 Skill 单独写叙事弧；检查普通内页的标题和小字是否足以独立读懂，不能只有十几字的概括，更不能通过增加同义句灌字。封面、原声与提问页可刻意留白。
4. **图片 QA**：公众号检查 AI 封面的中文字、视觉关系和裁切；图卡渲染前核对每页的字段、字量、重复内容和来源，确认后渲染并检查留白与溢出，区分内容不足与 CSS 布局问题。
5. 在交付回复中报告选题取舍、各篇正文的大致字数、图卡页数、短页的理由以及待核对的原话/授权；不要把制作进度塞进每期 README。

## 本期命令

公众号封面由 AI 按文章生成。确认小红书／视频号图文脚本后，在仓库根目录执行：

```bash
python3 scripts/render-publish.py {本期目录} --channel xhs --channel sph
```

图卡下载：GitHub Actions 的临时 Artifact（保留 1 天，不入库）；公众号封面由 AI 生图工具直接交付。
