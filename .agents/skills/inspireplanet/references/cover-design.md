# 公众号 AI 封面

公众号横版封面直接根据文章调用 AI 图像生成工具。小红书／视频号的首图继续随各自文字图卡生成，见 [图卡说明](../../../../scripts/text-cards/README.md)。

## 从文章到画面

1. 读完整篇文章，提取本篇独有的经历、问题、变化或动作。
2. 写一句可见的视觉关系：人物或物件如何接近、分开、遮挡、打开或改变。不要只列“阅读、成长、温暖”等抽象标签。
3. 选择适合该篇的风格、构图与配色，让画面本身承担内容关系；不固定双纸卡、箭头、书桌或咖啡模板，也不随机抽签。
4. 从正文选 6–14 字短副标题，补充而非重复正式文章标题。提示词逐字列明图上文案，只生成带字成品。
5. 在本期 `assets/cover-prompts.md` 按篇保存文章链接、副标题、视觉意图与实际提示词。提示词是可编辑源材料，不是程序配置。

## 生图与确认

- 默认使用当前环境内置的 AI 生图工具（如 `image_gen`）；每篇单独调用，不用 HTML/CSS、SVG 或浏览器截图代替生图。不自动改用付费 API 或要求用户提供密钥。
- 用户已经要求生成文章与封面时，直接完成文章后出图；只有明确要求先看方案、只写稿或暂不出图时才停在提示词。不因缺少“确认 JSON 配置”而中断请求。
- 目标为约 2.35:1 的宽横版，宽度尽量达到 1920px；按工具能力请求尺寸，为文字和主体预留裁切空间。报告经过核验的实际尺寸与格式。
- 不生成可识别真人，不伪造会议照片，不添加 Logo、水印、二维码或正文没有的营销结论。真实照片只在用户提供并授权时用作参考。
- 没有可用生图工具时，交付提示词并说明未生成；不要把提示词、概念描述或计划文件名称为封面成品。

## 提示词骨架

按文章自由组织，不必机械填满：

```text
用途：微信公众号横版封面，约 2.35:1。
文章核心：本篇真实经历或问题；不加入正文之外的事实。
画面：一个明确可见的动作或关系；说明主体、空间与视觉重点。
风格：根据文章选择媒介、色彩、光线与质感。
准确文案：“{6–14 字副标题}”，清晰中文，不增加其他文字。
限制：文字与主体留安全边距；无 Logo、水印、二维码、可识别真人或伪造现场。
```

## 检查与交付

- 检查中文准确完整、画面和正文相符、主体未裁掉、没有伪字或多余元素。不合格时通过 AI 工具定向修改或重生成。
- 直接展示生成图片，并沿用当前生图工具的交付方式。不提交成品图片、HTML 或 ZIP 到 Git，不声称图片由 Actions 生成或已进入 Artifact。
- 默认保留工具实际输出格式。确需 JPEG、压缩或精确尺寸时，在工具支持范围内导出并核验；不要承诺未经检查的格式、体积或分辨率。
- 生成图片不等于发布。文章署名、真实人物或家庭经历与公开范围仍需当事人确认。

历史 `assets/cover-configs.md` 或稿件里的 `cover-config` 仅为旧版记录；重做封面时从文章重新构思，不恢复旧代码渲染流程。
