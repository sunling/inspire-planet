# 封面设计原则与保存规范

## 设计原则

- 不只表现“开会、阅读、成长”这种题材类别；
- 咖啡、电脑、笔记本、耳机和窗边不是默认答案，只有能承担核心关系时才用；
- 不生成可识别真人，不虚构真实现场；
- 只做带字成品，不创建、不保存、不交付无字版本；
- 公众号横版：主体只放 6–14 字短副标题，补充发布标题；
- 小红书／视频号图集首图：主体放精简后的核心标题，必要时另加补充副标题，不机械重复；
- 副标题优先表达本篇独有的问题、变化、张力或行动，避免“关于成长的思考”这类通用文案；
- 不出现 Logo、水印、伪文字和营销海报感；
- 模板可以复用；纸卡上的具体内容与连接关系必须表达本篇选题，不只换颜色或套通用成长文案。

## 默认生成方式

- 先完成内容与配置，用户明确确认相关脚本后才出图；脚本文字或视觉命题改动后重新确认受影响部分。
- 配置中的 `asset` 和 `photo` 路径相对本期目录，Markdown 稿件链接相对 `cover/`（如 `../gzh-liying.md`）。
- 默认使用 HTML/CSS + 浏览器截图，主题为 `collage`（C 版纸张拼贴），不默认调用图像生成模型。
- 渲染器和配置格式见仓库根目录 `scripts/covers/README.md`；执行 `python3 scripts/covers/render.py events/{year}/{event}/cover/cover-configs.md`。所有渠道的完整配置、选定的封面文字、视觉命题和复用关系统一放入本期 `cover/cover-configs.md`，按篇目与渠道分节；不在渠道稿中重复保存配置。
- 主题通过 `theme` 或 `--theme` 选择；当前只实现 `collage`，以后按实际需求新增主题 CSS。
- 真实照片由用户提供并确认使用范围，支持本地照片路径和裁切焦点；先做样张再核对主体是否保留，不用生成图冒充现场。
- 仅用户明确需要插画等位图视觉时，再使用 imagegen；保留 HTML 文字排版与渠道分工。

## 出图流程

1. 完整读文章，提取本篇独有的核心变化、问题或动作；
2. 按渠道选定封面核心标题或短副标题，并按语义明确断行；
3. 把它转换成一句可见的空间关系或动作（视觉命题）；
4. 在本期 `cover/cover-configs.md` 的对应篇目与渠道小节写完整配置与视觉命题，交付封面脚本供用户审阅；
5. 用户明确确认图文脚本与封面脚本后，按主题独立构图并渲染完整带字封面；
6. 检查文字准确、完整、清晰，符合渠道的标题／副标题分工；检查裁切、溢出与重叠，不合格就调整；
7. 按下面的规范存 JPEG，并回报实际体积；用户要求渲染图集时，用渠道封面替换仓库外图集的 `01.jpg`，同步刷新总览和打包文件。

## 保存规范（JPEG）

- 一律 JPEG，不交付 PNG；
- 参数：`quality=88`、`optimize=True`、`progressive=True`；
- 保存前转 `RGB`；带 alpha 的先合成到设计底色，不留透明通道；
- 分辨率按渠道要求，不降；
- 单张目标 ≤400 KB；超出先降到 `quality=85`，再把 `subsampling` 设为 `2`（4:2:0），仍超出则简化照片／布局后重新保存，不降低规定分辨率；
- 保存后打印实际体积，超过 500 KB 视为不合格，重存。
