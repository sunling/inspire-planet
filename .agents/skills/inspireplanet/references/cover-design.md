# 封面设计原则与保存规范（公众号 / 小红书共用）

`inspireplanet-gzh`（公众号横版）与 `inspireplanet-xhs`（小红书竖版）共用这份判断标准。
各自只在 SKILL.md 里写自己的尺寸与构图差异，不在这里复制一份。

## 设计原则

- 先完整阅读文章，提取本期独有的核心变化、问题或动作；
- 不只表现“开会、阅读、成长”这种题材类别；
- 咖啡、电脑、笔记本、耳机和窗边不是默认答案；只有能承担核心关系时才使用；
- 不生成可识别真人，不虚构真实现场；
- 直接制作带字封面成品，不创建、不保存、不交付无字版本；
- 封面文字只放选定的最终副标题；副标题补充主标题的信息，不能照抄、改写或重复主标题；
- 副标题优先表达本期独有的问题、变化、张力或行动，避免“关于成长的思考”等通用文案；
- 不出现 Logo、水印、伪文字和营销海报感；
- 同一张图删掉文字后若可无差别用于最近三期，说明画面太通用，必须重做。

## 保存规范（JPEG）

封面成品一律输出 **JPEG**，不交付 PNG：

- 参数：`quality=88`、`optimize=True`、`progressive=True`；
- 保存前转 `RGB`；画面若带 alpha，先合成到设计底色，不留透明通道；
- 分辨率不降：公众号横版宽度保持 ≥1920px，小红书保持 1080×1440（3:4）；
- 单张目标 ≤ 400 KB；超出则先降到 `quality=85`，再把 `subsampling` 设为 `2`（4:2:0），仍超出再缩到宽 1600px；
- 保存后打印实际体积；超过 500 KB 视为不合格，重存；
- 平台上传直接用这个 JPEG，不再另存一份 PNG。

理由：同一张 1920px 封面，PNG 约 2 MB，JPEG q88 约 0.25 MB（小 8–10 倍），手机端肉眼无差别（实测平均像素差 2/255，99.9% 的像素差 ≤10/255）。封面每期都要进仓库，格式是长期体积的唯一杠杆——用 git 覆盖同名文件并不会让仓库变小，历史会保留每一版（实测：2 MB 的图覆盖 5 次，`.git` 从 2 MB 长到 10 MB）。

## 出图流程（两端通用）

1. 读文章，提取核心变化 / 问题 / 动作；
2. 选或克制调整一个不与主标题重复的 6–14 字最终副标题；
3. 把它转换成一句可见的空间关系或动作（视觉命题）；
4. 按该渠道的尺寸要求构图，加入中文副标题，只输出一张完整的带字封面；
5. 检查文字是否准确、完整、清晰，且没有与主标题表达相同信息；不合格就重做；
6. 按上面的保存规范存成 JPEG，并回报实际体积。
