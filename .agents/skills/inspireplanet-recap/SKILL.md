# Inspire Planet Recap

## 目标

把某期会议里**一位分享者的一件事**，写成一篇**独立成立、能被更多人看见**的公众号文章。

目标是让**分享本身被看见**，不是记录一场会议。一期有几位分享者时，产出一期多篇；不把所有人的内容压进一篇长文。

## 结构与长度

- `index.md`：本期**索引**（约 200–400 字）——一句话概括本期 + 每篇一行链接；没能成篇的内容用一两句收在“这一期还聊到”。索引是**仓库内材料，不单独发公众号**；
- `gzh-{slug}.md`：**分享文章**（约 800–2000 字），一篇只讲一个人的一件事，独立成篇；文件名用分享者英文小写 slug，如 `gzh-liying.md`、`gzh-sunling.md`；
- **一期通常只有 1–2 篇，不是每位分享者一篇**；只有一位撑得住时就只写一篇；
- **能不能成篇的判断**：假设读者只看到标题点进来，能不能读到三段有画面的内容？不能，就别单独成篇，收进索引；
- 长度由内容决定，不设硬下限；内容撑得住就写足。写不到 800 字，通常说明它还不该单独成篇；
- 不把不同人的分享硬压进一篇；也不为了凑一个统一主题而强行归并；
- 行动入口与二维码只放在 `index.md` 索引末尾，分享文章末尾不重复。

## Event 路径

```text
events/{year}/{YYYYMMDD}-epXX/
```

默认输入：

```text
transcript.txt
```

默认输出：

```text
index.md
```

相关产物：

- 发布辅助材料：`promo.md`；
- 金句 JSON：`quote-cards.json`；
- 封面：`assets/recap-cover.jpg`。

`index.md` 只保存本期索引（一行概括 + 各篇链接），不放文章正文。标题候选、摘要、社交文案和封面配置由 `promo.md` 承接，不追加到索引末尾。

会议纪要正文末尾固定保留“参与启发星球”的行动入口，包括一小段自然邀请和固定的微信社群二维码图片插入位。这属于文章发布结构，不属于 `promo.md` 的发布辅助文案。

## 开始前读取与 Loop

- 开始前读取 `AGENTS.md`；
- 需要活动时间、会议平台、加入方式或邀请语时，读取 `current.md`；
- 稳定的新偏好写入同目录的 `LEARNINGS.md`；典型改写样本写入 `EXAMPLES.md`；
- 不因一次生成自动更新这些文件。

## 严格边界

- 所有事实、故事、人物观点和资源都必须来自转写或可追溯材料；
- 只做必要整理，不改变原意，不拔高成鸡汤；
- 不从个人分享稿或会后日记补充会议事实；
- 涉及私人信息时删除可识别细节；
- 活动时间、会议 ID、加入方式和下一期信息都属于可能变化的运营信息，不写死在 Skill 中；
- `current.md` 中只有带验证状态、仍然有效的信息可以复用；`status: needs-verification` 时不能把其中待确认内容写进新稿。

## 文末行动入口

每篇会议纪要在正文自然结束后，用分隔线隔开并保留一个克制的行动入口：

1. 用 1–2 句话邀请读者参加线上会议、加入微信群或带着自己的经历来分享；
2. 紧接着插入固定的“启发星球·加入微信社群”二维码图片；
3. 图片承担主要行动说明，文字不要重复罗列图片上已经展示的全部参与方式；
4. 二维码图片必须使用用户确认的原图，不重新绘制、不生成近似二维码，也不从截图中猜测链接；
5. 图片尚未存入仓库时，在 `index.md` 中使用 HTML 注释标明发布插入位，例如：

```md
<!-- 发布时插入固定图片：启发星球·加入微信社群二维码 -->
```

固定行动入口与动态运营信息分开处理：固定图片可以每期复用；下一期日期、会议平台、会议 ID 和临时活动仍按 `current.md` 的验证规则处理。不要因为有固定二维码图片，就补写未经确认的时间或会议信息。

## 参会状态判断

孙玲是否真实参会，会直接影响纪要能否使用现场第一人称。不要仅凭转写前 30 行判断。

按以下顺序确认：

1. 先查看当前 event 中是否有明确记录的主持人、参会者或活动说明；
2. 检查转写中的说话人列表、主持开场、互动和孙玲实际发言；
3. 必要时搜索整份 transcript 中可确认的发言标识，而不是只看开头；
4. 用户已明确说明参会状态时，以用户说明为准；
5. 仍无法确认时，不假装在场，采用中性第三人称或明确写“根据会议转写整理”。

判断结果：

- **确认参会**：可以使用真实现场第一人称；
- **确认未参会**：必须写成会后阅读和整理转写的视角；
- **无法确认**：不写具体身体状态、位置或“我在现场发现”，并在完成反馈中说明待确认。

## 工作流程

1. 确认 event、日期、期数、输入 transcript 和参会状态；
2. 阅读完整转写并按发言人整理：具体经历、核心主题、关键判断、必要互动和真实行动；
3. 根据参会状态和真实材料，按下方“导语选择”写导语；
4. 每位核心分享者保留：
   - 一个具体场景或经历；
   - 2–4 个关键观点；
   - 一句真正推动主题的互动回应；
5. 资源放回对应分享者段落，不另建冗长资源清单；
6. 按「结构与长度」写：分享文章 800–2000 字，内容撑不住就不单独成篇；索引约 200–400 字；删掉寒暄、重复和旁枝，不硬凑；
7. 在正文结尾加入固定的“参与启发星球”行动入口和二维码图片插入位；
8. 下一期预告、会议时间、会议 ID 或其他动态加入方式，按“用户当前说明 → 当前 event → `current.md` 中仍有效的信息”的顺序读取；找不到时省略或标记待确认；
9. 用户要求修改已有纪要时，优先局部修改，并回到转写核对事实。

## 导语选择

孙玲真实参会时，不固定套用一种开头。按转写中最有力量的真实入口依次选择：

1. **现场瞬间**：有一句话、一个停顿或一次意外真正推动了讨论时，从那个瞬间进入；
2. **真实问题**：全场反复靠近同一个问题、但没有统一答案时，直接提出这个问题；
3. **主理人观察**：分享看似分散时，写出孙玲在倾听中发现的隐约连接；
4. **理解变化**：孙玲原来的判断在会议中确实发生变化时，从“我原来以为……”进入；
5. **开场状态**：以上入口都不明显时，才使用当时的位置、身体状态、环境或开场动作。

导语通常完成三件事：让读者进入真实现场，交代孙玲当时如何在场，并留下一个值得继续阅读的问题或连接。主题应从现场和分享中自然出现，不要提前替所有人总结结论。

不要每期机械重复日期、北京时间、西雅图时间、天气或“这一期内容跨度很大”。只有这些信息真正影响现场、理解或叙事时才保留。不要为了制造统一主题，强行把不同分享归到同一个答案下。

孙玲未参会或参会状态无法确认时，不使用现场第一人称，也不假装主题在现场被自己发现。

## 文章结构

索引（`index.md`，仓库内，不发公众号）：

```md
# EPXX｜本期索引

一句话概括本期

## 这一期有谁
- {名字}：[{这件事的题眼}](recap-1-{slug}.md)

---

参与启发星球的简短邀请

<!-- 发布时插入固定图片：启发星球·加入微信社群二维码 -->
```

分享文章（`gzh-{slug}.md`，发公众号）：

```md
# EPXX｜{名字}：{这件事或这个问题}

开头 2–3 句直接进入场景或问题——不写“这一期某某分享了……”。

正文：具体经历、关键观点、必要回应；靠细节和原话推进，不靠小标题。

结尾停在事情本身，不喊口号、不硬加结论。
```

分享文章的**开头**从这位分享者最有力量的真实入口进入：一个瞬间、一个具体场景、或一个真实问题。不要用“这一期”“我们聊到了”这类纪要式开场。

正文不做逐字会议纪要，也不把每个人的每句话都收进去。

## 完成后的回复

简短说明：

1. 写入或更新的文件（索引 + 各分享文章路径，以及每篇的字数）；
2. 参会状态及判断依据；
3. 本期纪要保留的主要人物和主题；
4. 哪些活动时间、加入方式、事实或隐私仍需确认。
