# 内容制作说明

每期以真实会议转写与回放为来源，按需制作文字、视频、音频；三条流程可独立进行，不要求每期全部完成。当前渠道安排保存在 [current.md](../current.md)，协作边界见 [AGENTS.md](../AGENTS.md)。

## 1. 准备素材

| 素材 | 获取与检查 | 放置位置 |
| --- | --- | --- |
| 会议转写 | GitHub Actions 定时尝试下载；历史会议按日期补录，核对期数与公开授权 | `events/{year}/{YYYYMMDD}-epXX/transcript.txt`；期次不确定时暂存 `incoming/meetings/` |
| 原始音视频 | 默认只需手动下载一份带声音的回放视频，切片和播客共用；无需另下音频。已有纯音频也可使用。提供本地路径，核对内容、日期、期数和音视频轨 | 被 Git 忽略的 `replays/`，沿用实际位置，不移动或覆盖源文件 |
| 当期备注 | 阅读本期 README 的署名、授权、隐私与事实待核对项 | 本期 `README.md` |

转写获取见 [会议转写说明](meeting-content.md)。工作流会直接提交公开 `main`，包括期次不确定时的暂存文件，运行前须确认可公开；已有本期转写不重复下载。原始转写不随编辑稿润色；本地回放不上传识别服务。

## 2. 文字：公众号，知乎待开通

**输入**：本期转写与发布备注。**交付**：一篇或多篇独立文章，每篇一个人一件事；正文、标题、两个备选标题与 120 字以内摘要统一保存在 `gzh-{slug}.md`。

使用 [inspireplanet-gzh](../.agents/skills/inspireplanet-gzh/SKILL.md)：

1. 通读转写，选出能独立成篇的真实经历；材料不足则不勉强成篇。
2. 按分享者第一人称口述整理，保留具体细节、现场追问与尚未解决的问题，署名归分享者；不从个人日记等私人来源补造会议事实。
3. 反查转写，交本人核对内容、署名及涉及的他人信息。未获准公开的材料保留在私人来源，不能因提交 Draft PR 就视为未公开。
4. 用户在公众号发布，或明确授权后代为操作；将实际日期和链接记录在本期 README 的发布备注。

> 使用 inspireplanet-gzh，基于 EPXX 的真实转写整理能独立成篇的公众号文章，交付标题、摘要和待核对事项。

知乎计划开通。开通后再按具体发布形式适配已审阅文章，保留事实与署名，并核对知乎公开范围；当前不新增空的知乎稿件、平台链接或自动发布流程。

## 3. 视频：视频号、小红书

**输入**：本地回放与本期转写。**交付**：原声短视频、SRT／ASS 字幕、检查预览及分别适配两平台的标题、正文、话题；独立封面按需制作。

使用 [inspireplanet-clips](../.agents/skills/inspireplanet-clips/SKILL.md)：

1. 检查回放，推荐能独立听懂的候选片段，说明分享者、来源位置、理由和待核对点。
2. 用户确认选段后，用实际媒体时间对齐原声、字幕和剪辑单，不直接把转写时间当切点。
3. 导出初剪，检查画面、字幕、句首句尾、跳切、音量与平台叠字空间；默认用视频首帧作封面。
4. 用户审片并确认原声、肖像、他人话语与具体内容的公开范围；确认选段不等于确认成片或授权发布。
5. 用户分别上传视频号、小红书，或明确授权后代为操作；使用对应平台文案，记录实际平台链接。

> 使用 inspireplanet-clips，检查本期本地回放和转写，推荐选段；我确认后制作初剪、字幕及视频号和小红书文案。

回放、候选、识别结果、剪辑单、字幕、`clip-{slug}.md`、封面与成片留在本地 `replays/`。本期 README 只记录可公开的实际发布链接与备注，不记录私人路径或制作进度。旧 `xhs-*.md`、`sph-*.md` 图文渲染脚本已清理，历史版本可从 Git 查阅；不沿用旧图文脚本和出图工具。

## 4. 音频：小宇宙，一期一集

**输入**：优先复用制作切片的同一份带声音的本地回放视频，由工具读取音轨；只有音频时也可直接使用。另需本期转写与发布备注。**交付**：一期一集的轻剪音频、标题、简介、参与者与剪辑后的时间轴，暂时只面向小宇宙。

使用 [inspireplanet-podcast](../.agents/skills/inspireplanet-podcast/SKILL.md)：

1. 核对回放，定位现场开场、各话题和自然道别。默认不另录片头片尾、不加 AI 配音或音乐，不追求固定时长。
2. 清理等待、设备操作、明显重复和明确长空白，保留自然语气与不同观点；静音检测只标候选，不批量删除口头禅。
3. 在本地剪辑单中记录源媒体秒数、删减理由及依据，生成成品音频和映射后的话题时间轴。
4. 检查整集解码、时长、响度、剪接处与各人听感；区分局部识别、技术检查和完整听审，不把工具成功写成已全场听审。
5. 用户试听并确认声音、署名和具体内容的公开范围，再在小宇宙上传音频，填写标题、简介、成品时间轴、本期详情页链接与指向 `/join` 的固定加入二维码图片，核对预览后发布；代操作仍需明确指令。
6. 获准公开后，将干净的最终文字整理成当期 `podcast.md`；发布后补实际小宇宙单集链接、实际时长及发布日期，在本期 README 加导航。音频或剪辑版本改变时同步更新时间轴，不能沿用旧时间码。

> 使用 inspireplanet-podcast，将 EPXX 本地回放按 MVP 轻剪成一集小宇宙播客，附标题、简介和成品时间轴，先交本地试听稿。

本地工具、剪辑单格式与检查命令见 skill 的 [工具说明](../.agents/skills/inspireplanet-podcast/references/tools.md)。工具产出的是本地文件，不自动上传小宇宙；账号、节目设置与平台当前上传要求在实际发布时核对，不在此固化未经验证的限制。

### 播客与会后文字的交接

完整流程优先：核实可访问的本期页 → 播客制作、试听与发布 → `podcast.md` 回填真实单集链接、实际时长和发布日期 → 生成回顾、金句与群消息 → 核对本期页面后发群。用户只做单项或播客暂缓时不强行等待。

Show notes 用本期详情页作为主要内容入口，另附用户已有的固定加入二维码图片，扫码到 `/join`，由加入页承接管理员每周更换的微信群二维码。固定图片的具体素材位置使用时核实；不替换成动态群二维码或分享者群二维码，也不凭空写图片地址。平台插图与最终显示在发布时核验，不能插图时再用加入页文字链接备用。

## 5. 网站回顾、金句与会后群消息

网站内容独立按需制作，不要求跟文章、短视频或播客同时完成。

| 产物 | 输入与用途 | 制作入口 |
| --- | --- | --- |
| `summary.json` | 围绕具体经历、追问和不同处境整理可简读、可展开的单期回顾 | [纪要 skill](../.agents/skills/inspireplanet-summary/SKILL.md) |
| `quote-cards.json` | 保留发言归属和可追溯语境，供网站金句卡片使用 | [金句 skill](../.agents/skills/inspireplanet-cards/SKILL.md) |
| `group-message.md` | 从本期选一个能独立读懂的交流片段，配一个已核实回顾链接，便于会后发群 | [回顾与群消息 skill](../.agents/skills/inspireplanet-summary/SKILL.md) |

> 使用 inspireplanet，基于本期转写按需整理文章、纪要或金句，核对事实与署名后更新已有稿件和导航。

回顾与群消息默认一起制作，用户只要求其中一项时只交该项。群消息只保留一个主要入口，不把回顾、金句、播客和文章链接一次全部发群。没有已核实的本期回顾链接时先交无链接正文，在交付说明中列待补项；音频是否已发布、回顾页是否能收听均需核实。只准备消息，不自动发群。

字段与网站同步遵循 [内容数据约定](../events/data-contract.md)。网站从本仓库 `main` 读取内容；未经确认的 JSON 不合入该分支。新增 `podcast.md` 仅作文字归档，不代表网站已支持展示播客或自动读取音频。

## 6. 存放、审核与发布回填

| 阶段／资料 | 保存位置 | 维护方式 |
| --- | --- | --- |
| 获准公开的转写、文章、纪要、金句 | 当期 `events/` | 按交付物维护一份正式源稿，原转写不润色 |
| 媒体、识别结果、剪辑单、字幕、审核与技术记录 | 本地 `replays/` | 不提交 GitHub，需自行备份 |
| 制作中的播客 `show-notes.md` | 本地播客制作目录 | 可分发布文案和内部备注；提交前不能整份复制 |
| 获准公开的播客标题、简介、参与者、成品时间轴、本期页、固定加入图片与发布信息 | 当期 `podcast.md` | 与发布版本一致，去掉内部备注、私人路径及未获准公开的信息；不复制成第二份长期正式稿 |
| 当期导航、公开授权备注、实际发布日期与链接 | 当期 `README.md` | 只链接已存在文件和真实发布页面，不写制作进度或推测链接 |

文章由署名本人过目；视频需审片；音频需试听。所有渠道分别确认具体公开范围，不能用某篇文章的同意替代原声或肖像授权。仅分享本地文件供试听与向平台发布是不同动作。

公开 GitHub 分支和 Draft PR 同样是公开空间。含隐私或尚未授权的内容留在本地／私人来源；通用工具、结构或 skill 变更使用独立分支与 Draft PR。公开文件修改后运行 `python3 scripts/check-content.py`。

平台发布或网站修改须有用户明确指令。发布后回填真实链接，未发布则不填“已发布”；活动安排、入口与渠道状态只复用 [current.md](../current.md) 已确认部分。
